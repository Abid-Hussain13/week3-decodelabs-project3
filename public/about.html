A small archive with a permanent address.

Quire is a writing site built as DecodeLabs Full Stack Project 3 — database integration done properly, without the ceremony.

Storage

PostgreSQL, not a notepad

Every entry lives in a real relational database — categories, drafts, timestamps, and all. Nothing is held in a temporary variable.

Operations

Full CRUD

Create, read, update, and delete posts through a JSON API with validation, parameterised queries, and sensible errors.

Interface

Five plain pages

Index, entry, about, desk, and editor. Server-rendered feel, no framework, no build step — just HTML, CSS, and fetch.

Why it looks like this

Most blogs are a grid of identical cards. Quire is built as an accession index: entries are numbered, filed under a section, and dated — the way a working archive keeps track of what it holds. The blue rule that appears on hover is the only flourish; everything else is typography and spacing.

Articles are set in Newsreader for long-form reading, Archivo for structure, and IBM Plex Mono for the machine-readable parts — dates, entry numbers, status badges.

The schema

Two tables. categories and posts, related one-to-many with a foreign key. Posts carry a status (draft or published), a computed reading time, and both created_at and published_at so the index can sort by what readers actually see.

Running it locally

Copy .env.example to .env, point DATABASE_URL at your Postgres instance, then run the schema and seed scripts before starting the server. The full sequence is in the README.
